# 予約のお知らせメール（Resend + Cloudflare Workers）

予約完了・取消・日時変更・前日のお知らせを、お客様にメールで送ります。
どれも無料枠の範囲で使えます（Resend は1日100通・月3,000通まで、Cloudflare Workers は1日10万回まで）。

## 送るメール

| いつ | だれに |
| --- | --- |
| 予約したとき（本人・トレーナーの代理予約） | お客様。本人が予約したときはお店にも |
| 取り消したとき（本人・お店側） | お客様。本人が取り消したときはお店にも |
| 日時を変えたとき（本人・トレーナー） | お客様。本人が変えたときはお店にも |
| 前日 18:00 | 翌日に予約があるお客様（`GOOGLE_SA` を入れたときだけ） |

宛先は、会員はログインしたメールアドレス、ゲストは申込のときに入れたメールアドレスです。

## 2段階で始められます

Resend は「お店のドメイン」を認証しないと、登録したご自分のアドレスにしか送れません。
そこで `MEMBER_MAIL` で、送る相手を切り替えられるようにしています。

| `MEMBER_MAIL` | 送るメール | 必要なもの |
| --- | --- | --- |
| `"off"`（最初はこちら） | お店への通知だけ（新しいご予約・取消・日時変更） | Resend と Cloudflare のアカウントだけ。ドメインは不要 |
| `"on"` | お客様への予約完了メールなども送る | お店のドメインと、その認証（DNS の設定） |

はじめは `SHOP_EMAIL` にお店のアドレスを入れ、`MEMBER_MAIL = "off"` で始めます。
**Resend のアカウントは、この `SHOP_EMAIL` と同じアドレスで作ってください。**
ドメインを認証していないあいだ、Resend はそのアドレスにしか送れないためです。

## 準備

1. **Resend**（https://resend.com）でアカウントを作る
   - 上に書いたお店のアドレスで登録する
   - 「API Keys」で API キーを作る（`re_` で始まる文字列）
   - お客様にも送りたくなったら、「Domains」でお店のドメインを追加し、
     表示された DNS の設定をドメインの管理画面に入れて認証する
2. **Cloudflare**（https://dash.cloudflare.com）でアカウントを作る（無料プラン）
3. `wrangler.toml` の `[vars]` を店舗に合わせて書き換える
   - `SHOP_EMAIL` に、お店で通知を受け取るアドレスを入れる
   - `MAIL_FROM` は、ドメインを認証するまで `onboarding@resend.dev` のままでよい
   - ドメインを認証したら `MAIL_FROM` をそのドメインのアドレスにして、`MEMBER_MAIL` を `"on"` にする
4. このフォルダで Worker を公開する

   ```bash
   npx wrangler login
   npx wrangler secret put RESEND_API_KEY
   npx wrangler deploy
   ```

   最後に表示される `https://〇〇-mail.△△.workers.dev` を控える
5. アプリの `config.js` の `mailEndpoint` に、控えた URL を入れて、アプリを公開し直す

`MEMBER_MAIL` や `MAIL_FROM` を変えたときは、`npx wrangler deploy` をやり直すだけです
（アプリ側は変えなくてかまいません）。

### 前日のお知らせを使う場合（任意）

前日のお知らせは、お客様がアプリを開いていないときに送るため、Firestore を読むための「サービスアカウント」が必要です。

1. Google Cloud コンソールの「IAM と管理」→「サービスアカウント」で、Firebase のプロジェクトにサービスアカウントを作る
2. ロールに「Cloud Datastore ユーザー」を付ける
3. 「鍵」→「鍵を追加」→「JSON」で鍵のファイルをダウンロードする
4. 次のコマンドで、ファイルの中身をそのまま貼り付ける

   ```bash
   npx wrangler secret put GOOGLE_SA
   ```

鍵のファイルは、ほかの人に渡したり、GitHub に入れたりしないでください。

## 安全のための仕組み

- アプリから届いた依頼は、Firebase のログイン情報（ID トークン）を確かめてから受け付けます
- 本人の予約か、トレーナーからの依頼だけを受け付けます
- 文面はこの Worker で決めたものだけです。アプリから本文を送ることはできません
- `ALLOWED_ORIGIN` に書いたサイト以外からは呼べません
